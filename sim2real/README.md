# 로봇 손 강화학습 정책 실기 실행

학습된 PPO 모델을 DYNAMIXEL 모터 4개에 연결하는 코드입니다. 모터의 실제 위치·속도를 입력으로 정책을 추론하고, 출력된 목표 위치를 모터 명령으로 변환합니다.

## 파일 구존

```text
sim2real/
   ├─ README.md
   ├─ finger_robot_ppo_best.zip # 학습된 PPO 정책 모델
   ├─ requirements.txt         # Python 패키지 목록
   ├─ apply_policy.py          # 초기 이동 및 실기 실행
   ├─ bus.py                   # DYNAMIXEL 통신
   ├─ core.py                  # 정책·모터 좌표 변환과 유효성 검사
   ├─ run.py                   # 모델 로딩 및 규격·해시 확인
   ├─ position_compensation.py # 실제 위치 오차 보정
   └─ config.provisional.json  # 모터 매핑·위치 기준·변환 계수
```


## 제어 구조

```text
초기 위치로 이동 → 실제 도달 확인
→ 모터 위치·속도 읽기 → 정책 입력 변환 → PPO 추론
→ 목표 위치 변환 → 추가 위치 보정 → 모터 명령 전송
```

- 하드웨어: XL330-M288, 모터 ID1~4, 모드5(Current-based Position Control). 손목은 제외합니다.
- 정책 순서: right / front / left / back → ID4 / ID1 / ID2 / ID3.
- 입력: 변환된 위치4개와 속도4개. 출력: 정규화된 절대 목표 위치4개.
- 감김 방향: 모터 위치값이 감소하는 방향입니다.
- 정책 실행 주기: 명목 30ms. 모터 내부 제어기는 이와 별도로 목표 위치를 추종합니다.
- 추가 보정: 실제 위치가 정책 목표에 못 미치면 더 당기는 명령을 제한적으로 누적합니다. 정책 목표 자체와 보정 명령은 별도로 기록합니다.
- 추가 보정 사용 시 모터 I 게인은0으로 설정합니다. 종료 후 변경한 게인·속도 프로파일을 복원합니다.

## 설치 및 실행

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

현재 시험 설정:

```powershell
python apply_policy.py --execute --seconds 10 --position-p 1000 --position-i 0 --profile-velocity 80 --profile-acceleration 40 --position-compensation 100
```

**이 명령은 실제 모터를 움직입니다.** 저장된 초기 위치로 이동한 뒤 정책을10초 실행합니다. 종료·오류·Ctrl+C 시 토크 OFF를 시도하고 결과를 기록합니다.

| 옵션 | 의미 |
| --- | --- |
| `--execute` | 실제 모터 구동. 생략하면 센서 읽기·추론만 수행 |
| `--seconds` | 초기 이동 이후 정책 실행 시간 |
| `--position-p`, `--position-i` | 모터 위치 제어 게인 |
| `--profile-velocity`, `--profile-acceleration` | 모터 속도·가속도 프로파일 설정값 |
| `--position-compensation` | 추가 당김 보정 상한, 0~200tick. 0이면 보정 비활성화 |

### 이 설정을 사용하는 이유

실기에서 모터가 정책의 목표 위치까지 도달하지 못하고 중간에 멈추는 문제가 있어, 위치 제어 게인을 조정하고 실제 위치 오차에 따른 추가 보정을 적용했습니다. 또한 낮은 속도 설정에서는 동작이 느리고 제한을 해제하면 급격하게 움직여, 속도와 가속도를 조정했습니다. 위 명령은 이러한 문제를 줄이기 위해 사용한 실기 시험 설정입니다.

프로파일 옵션은 레지스터 값이며, 0은 정지가 아니라 프로파일 제한 해제를 뜻합니다. 위 값들은 실기 시험 설정이며 다른 하드웨어에 그대로 적용할 기준은 아닙니다.

실행 전 확인 사항:

- 현재 포트와 통신속도는 `apply_policy.py`에 **COM8 / 1,000,000bps**로 지정되어 있습니다. 다른 PC에서는 해당 부분을 수정합니다.
- 모터는 토크 OFF, 모드5, Drive Mode0, 장치 오류 없음 상태여야 합니다.
- `config.provisional.json`의 위치 기준·모터 매핑이 실제 조립 상태와 일치해야 합니다.
- 모델 교체 시 입출력 의미를 확인하고 설정의 SHA256을 갱신해야 합니다.

전류 상한700mA, 위치 범위, 장치 온도 설정, 오래된 센서값 및 통신 오류에 대한 검사가 포함됩니다. 통신 단절 시 토크 OFF가 확인되지 않을 수 있습니다.

## 결과 확인

실행 로그는 `hardware_bridge/logs/`에 생성됩니다.

| 로그 필드 | 의미 |
| --- | --- |
| `policy_goal_tick` | 정책이 요구한 모터 위치 |
| `limited_targets_tick` | 추가 보정 후 전송할 모터 명령 |
| `position_tick` | 엔코더에서 읽은 실제 모터 위치 |
| `position_trajectory_tick` | 모터 내부에서 생성한 중간 목표 |
| `current_ma`, `present_pwm_raw`, `input_voltage_v` | 측정 전류·PWM 출력·전압 |
| `fault`, `stop` | 중단 원인과 토크 OFF 확인 결과 |

정책 목표 도달 여부는 **`policy_goal_tick`과 `position_tick`**을 비교합니다. 모터 위치 도달이 손가락의 원하는 굽힘이나 물체 파지 성공을 뜻하지는 않습니다.

## 현재 확인된 문제

- **목표 위치 추종 오차:** 정책 목표를 모터에 전달해도 실제 위치가 목표에 도달하지 않고 멈추는 구간이 있습니다. 추가 위치 보정으로 오차가 줄었지만 모든 모터에서 해소되지는 않았습니다.
- **모터 위치와 손가락 굽힘의 차이:** 모터가 목표에 가까워져도 손가락이 충분히 굽지 않는 경우가 있습니다. 텐던 장력·미끄러짐·마찰 및 위치 변환 관계를 확인해야 하며, 원인은 아직 확정되지 않았습니다.
- **시뮬과 실기의 구동 특성 차이:** 같은 목표라도 속도·힘·가속도·지연이 다릅니다. 현재 실기 게인과 추가 보정은 시뮬에서 학습한 구동 모델과 동일하게 검증된 설정이 아닙니다.
- **관측값과 실행 주기의 차이:** 시뮬은 관절각 합으로 구성된 텐던 상태를 관측하지만 실기는 모터 위치·속도를 변환해 사용합니다. 이 대응 관계는 임시 보정이며, 로컬 시뮬의 정책 주기 2ms와 실기 명목 30ms도 다릅니다.
